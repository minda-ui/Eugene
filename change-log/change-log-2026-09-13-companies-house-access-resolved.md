## Runbook-Companies-House-Access-for-Peter → v0.2 (RESOLVED)

**Finding.** The gov.uk / Companies House egress block is the **organisation's network egress policy**
(a proxy 403/407-class denial), reproducible even from an interactive session. It is **not** a
per-routine or per-connector setting, and the routine editor exposes **no domain allowlist** — so the
v0.1 runbook step ("allowlist the four gov.uk domains") was never a lever the user actually had. Per
environment policy, an egress denial is reported and worked around with a *supported* mechanism, not
bypassed.

**Fix (better than v0.1).** Claude Code cloud environments expose **API credentials** whose hosts
"become reachable even when Network access wouldn't otherwise allow them," with values stored
**write-only** (never reach the session). So Minda added, in the environment settings:

- Name **Companies House API**, type **Basic**, allowed website
  **`api.company-information.service.gov.uk`**, **Username** = a free Companies House REST API key
  (Live application, API-key client type, registered by Minda), **Password** blank.

This opens exactly the one host **and** keeps the key out of the session — satisfying charter §3
(Eugene/Peter never hold secrets) more cleanly than an environment secret would. Eugene remained
guide-only: the key issuance and credential entry were Minda's console actions; Eugene never held the
key.
